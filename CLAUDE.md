# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project in one line

Property Pulse ("PropPulse — Tycoon Edition") is a zero-build, single-file Thai-language PWA (`index.html`) for a landlord tracking a small personal rental property portfolio — rent collection, loan payments, expenses, tax reporting — persisted entirely client-side in IndexedDB. No backend, no package manager, no bundler.

See `context.md` for the full architectural write-up and `agents.md` for agent-specific editing conventions — both are kept in this repo and should be treated as authoritative alongside this file.

## Repo layout

```
index.html      Everything: markup, CSS (Tailwind CDN utility classes + a
                 <style> block), and all JS in one <script> block (~130KB).
manifest.json    PWA manifest (name, icons, theme colors, start_url).
sw.js            Service worker — cache-first for the app shell, network-
                 first (cache fallback) for CDN assets.
icons/           App icons (icon.svg source, icon-192.png, icon-512.png,
                 icon-maskable.png), generated by make_icons.py.
make_icons.py    One-off Python/Pillow script that draws/exports the PNG
                 icon set. Not run automatically.
```

No `src/`, `tests/`, `dist/`, `package.json`, bundler, or linter config exists. The app ships as-is to GitHub Pages (`https://supasiao7896th.github.io/Property-Pulse/`, hardcoded in the Settings share link).

## Commands

There is no build, lint, or test tooling. To preview the app locally (a real HTTP origin is required for the service worker to register — opening `index.html` via `file://` breaks that):

```bash
python3 -m http.server 8000   # from the repo root, then open http://localhost:8000/
```

To regenerate icons after changing icon design (requires Pillow):

```bash
python3 make_icons.py
```

Verification is entirely manual since there's no automated test suite/CI:
1. Serve the directory and open it in a browser; exercise the specific view you changed (Dashboard, Rooms, Transactions, Settings).
2. Check the browser console for JS errors — nothing catches syntax mistakes ahead of time.
3. If you touched IndexedDB schema/persistence: test Export DB → Import DB round-trip in Settings, and test against a fresh IndexedDB (clear site data) to confirm `onupgradeneeded` still builds a working DB from scratch.

## Architecture (inside `index.html`)

- **Dependencies**, all via CDN (no `node_modules`): Tailwind CSS, Chart.js (`cdn.jsdelivr.net` — currently loaded but unused, the cash-flow chart was removed), Lucide icons (`unpkg.com`), Google Fonts (Sarabun).
- **CSP** is set via a `<meta>` tag in `<head>`. It still allow-lists `https://generativelanguage.googleapis.com` in `connect-src` even though the Gemini AI integration was removed (`remove: Gemini AI Engine`). Don't reintroduce AI/network calls without explicit product direction; tighten the CSP rather than loosen it.
- **Persistence**: IndexedDB via the `DBManager` IIFE (~`index.html:848`). DB name `PropertyPulseDB_V4`, `CONFIG.DB_VERSION` currently `2`, stores: `rooms`, `transactions`, `settings`, `documents` (indexed by `roomId`). No `localStorage` for app data. IndexedDB is the single source of truth — in-memory `state` is a cache populated on `start()` and kept in sync by re-fetching/re-rendering after writes.
- **App module**: the `App` IIFE (~`index.html:889`) owns all state and rendering. State shape: `{ rooms: [], transactions: [], viewMode: 'month' }`. Plain imperative DOM manipulation — no framework, no virtual DOM. Views toggle via the `.active` class on `<section id="view-*">` (`switchView`, ~`index.html:1369`).
- **Views** (`data-view` nav attr): `dashboard` (income/expense/net, occupancy, rent-collected progress, per-unit performance), `rooms` ("พอร์ตโฟลิโอ" — unit registration, tenant info, loan amortization via `calcLoanCurrentBalance`/`calcLoanSchedule`, move-out workflow, document gallery, invoice generation/print), `transactions` ("สมุดบัญชีแยกประเภท" — income/expense entries against `CONFIG.CATEGORIES`, filterable history, annual tax report via `generateTaxReport`), `settings` (share link, Export/Import DB as JSON, reset data).
- **UX helpers worth knowing**: custom toast (`showToast`), custom confirm dialog (`customConfirm`, not `window.confirm`), Thai month formatting (`thaiMonths`, `fmtMonthThai` — includes Buddhist Era `+543` conversion), `escHtml` for manual XSS-safe interpolation into `innerHTML`.

## Editing conventions

- Keep the **single-file, zero-build** architecture. Do not add a bundler, npm dependencies, or split into modules/files unless explicitly asked — this is a deliberate constraint, not an oversight.
- All user-facing strings are **Thai**. Match existing tone/terminology (e.g. "ยูนิต" for unit, "ยอดเงิน" for amount).
- Match existing code style: vanilla JS, IIFE module pattern (`DBManager`, `App`), `const`-first, template-string-built DOM via `innerHTML`.
- Money is always formatted via `formatMoney`/`formatMoneyShort` (`Intl.NumberFormat('th-TH', { style: 'currency', currency: 'THB' })`) — don't hand-roll currency formatting.
- Escape interpolated user data with `escHtml` when building `innerHTML` strings — the CSP allows `'unsafe-inline'` scripts but stored data still must not be trusted blindly when rendered.
- After injecting markup with `data-lucide` attributes, call `lucide.createIcons({root: ...})` so icons render.
- If you change the `documents`/`rooms`/`transactions`/`settings` schema, bump `CONFIG.DB_VERSION` and handle migration in `DBManager.init`'s `onupgradeneeded` handler.
- Service worker caches `./`, `./index.html`, `./manifest.json`, `./icons/icon.svg` as `APP_SHELL`. If you rename/move any of those files, update `APP_SHELL` in `sw.js` and bump the `CACHE` constant so old caches are purged on next activate.
- Don't reintroduce Chart.js usage casually — it's loaded but currently unused; if you add a chart back, make it an intentional feature, not leftover scaffolding.
